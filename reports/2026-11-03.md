### [今後のセキュリティの考え方](https://zenn.dev/cscloud_blog/articles/a987163efae5d8)
> AIによって環境移行の工数が下がった今こそ、クラウドセキュリティのアーキテクチャを根本から見直すべきと提案する記事。SSHポートを閉じてSession Managerを使う、S3+CloudFrontで静的コンテンツを配信する、GuardDutyの過検知を減らす運用に変えるなど具体的な改善策を紹介。攻撃面の縮小と責任をクラウドベンダーに委ねることで、重要な意思決定に集中できる体制を推奨している。

### [3 人それぞれの Claude Code を Slack でつないで ISUCON2026 に参加した（207,039 点）](https://zenn.dev/kauche/articles/f3736c660aab77)
> 3名がそれぞれのPCでClaude Codeを動かし、Slackを通じてエージェント同士を連携させてISUCON2026に参加した体験記。後半は人間がコードを書かず、GOAL.mdに目標と約束事を書いてAIエージェントに委ねる形をとり、最終スコア207,039点を記録した。デプロイとベンチマークが衝突しないよう調整しながらエージェントを協調動作させた点が新しい取り組みとして注目されている。

### [日本の全法令を git の履歴にしてみた](https://zenn.dev/koheiwada/articles/houritsu-japanese-laws-as-git)
> e-Gov法令APIv2から日本の全法令を取得し、改正法1本の施行を1コミットとするGitリポジトリ「houritsu」を作成したプロジェクト。コミット日を施行日に設定することで、`git log`や`git diff`を使って法律がいつどこで変わったかを追跡できるようにした。法令改正履歴をバージョン管理システムで可視化するという独創的なアプローチが話題になっている。

### [GitHub Actions で checkout@v7 のようなバージョン指定を書くのはやめよう！ 時代は actions.lock！](https://zenn.dev/progate/articles/24b1140180300c)
> GitHub Actionsでタグ指定（`@v7`など）を使うと、攻撃者がタグを別のコミットに付け替えることで悪意のあるコードを実行させられるサプライチェーン攻撃のリスクがあると解説した記事。`actions.lock`というロックファイルに使用するActionのコミットSHAを記録することで安全性を確保でき、`gh actions-lock`コマンドで生成・更新できる。
